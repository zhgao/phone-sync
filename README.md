# PhoneSync — 手机照片自动同步到 Mac

手机连上家里 WiFi，照片**自动**传到 Mac。不用打开网页，不用点按钮。

**照片存到：** `~/Pictures/手机照片/`

---

## 你需要做什么

### Mac 端：一条命令

```bash
bash 一键安装.command
```

或者直接双击那个文件。装完之后**永远不用管** —— 开机自启、崩溃自动重启。

### 手机端：一次配置，永久有效

用数据线连 Mac，跑：

```bash
bash 一键配置手机.command
```

脚本自动做：装 APK、关电池优化、授予权限。

**还剩 4 步要在 Syncthing App 里点**（约 3 分钟，只做一次）：

1. 添加远程设备，粘贴设备 ID（安装器会显示，直接复制）
2. 添加文件夹 `DCIM/Camera`，类型选「发送」
3. 打开该文件夹的「共享」，勾选你的 Mac
4. 手机系统设置里开「允许自启动」

之后：到家连 WiFi，自动同步。

## 工作原理

```
   OPPO 手机                            Mac
 +--------------+                +-----------------+
 | 相机         |                |                 |
 |   DCIM/      |   局域网直连    |   Syncthing     |
 |   Camera     | -------------> |      |          |
 |              |  点对点加密     |      v          |
 | 常驻后台     |  不经过任何云   |  ~/Pictures/    |
 | (系统级App)  |                |    手机照片/     |
 +--------------+                +-----------------+
        ^                               ^
  连上家里WiFi就自动跑           开机自启 + 崩溃重启
```

用的是 Syncthing —— 开源、成熟、点对点加密、**不经过任何云服务器**。
照片从手机直传到你的 Mac。

**为什么必须用 App 而不是网页：**

浏览器不能静默读相册、不能常驻后台、读不到 WiFi 名称。
网页方案的上限是"你手动打开页面点一下"。
要做到真自动，必须有系统级常驻程序 —— 这是 Android / iOS 的安全设计。

## 三个必须知道的限制

### 1. MacBook 合盖 = 同步暂停

Apple 硬件限制，没有软件能绕。实际情况：

| Mac 状态 | 表现 |
|---|---|
| 开着 / 刚唤醒 | 秒级同步 |
| 合盖睡眠 | 暂停，**唤醒后自动补传**（Syncthing 内置机制） |

MacBook 自带键盘，合盖睡不了。要合盖用笔记本支架模式，或插电后用 `caffeinate -i` 阻止空闲睡眠。

### 2. 出门在外也会同步

Syncthing 默认走中继服务器，所以在外面用流量也会传。
想改成「只在家同步」：Syncthing App → 设置 → 连接 → 打开「仅 WiFi 时同步」。

### 3. 微信小程序做不到这件事

小程序没有相册权限、没有常驻后台、读不到 WiFi 名称。
如果你期待过「微信小程序自动同步照片」，那在技术上不存在。

## 装完之后在哪看

| 位置 | 内容 |
|---|---|
| `~/Pictures/手机照片/` | 同步过来的照片，按手机原有目录结构 |
| http://192.168.0.100:8384 | Web 管理界面（手机也能开） |
| `~/.phonesync/syncthing.out.log` | 运行日志 |

Web UI 可以看同步进度、设备状态、冲突文件。平时不用开，出问题再看。

## 常见问题

| 现象 | 原因和解决 |
|---|---|
| 手机搜不到 Mac | 确认两台在同一 WiFi；Mac 上 `open -a Syncthing` 启动 |
| 连上了但不传 | 检查文件夹的「共享」里有没有勾 Mac |
| 息屏后就不传了 | 电池优化没设「不限制」，或最近任务没加锁 |
| Mac 睡眠后没补传 | 睡眠期间确实收不到，唤醒后自动继续 |
| 提示「未受信任的设备」 | Syncthing 首次连接会弹确认框，点信任 |
| 传到一半断了 | 断点续传内置，下次连上自动继续，不用管 |

### 重装系统 / 换电脑

```bash
git clone https://github.com/zhgao/phone-sync.git
cd phone-sync
bash 一键安装.command
```

Mac 端全新装好。手机端 Syncthing 还在，只需重新添加这台 Mac（用新设备 ID）。

## 安全

- 只在局域网内点对点传输，**照片不经过任何云服务器**
- Web UI 只绑局域网（`0.0.0.0:8384`），不暴露到公网
- 传输走 Syncthing 设备密钥加密
- 想彻底关掉：`launchctl bootout gui/$(id -u)/com.syncthing.syncthing`

## 项目结构

```
phone-sync/
├── 一键安装.command          # Mac 端一键安装（双击运行）
├── 一键配置手机.command       # 手机端一键配置（需数据线）
├── scripts/
│   ├── setup-syncthing.sh    # 配 Web UI 绑定 + 局域网发现
│   ├── install-syncthing-autostart.sh  # 开机自启 + 真就绪验证
│   └── setup-folder-api.py   # 通过 REST API 创建共享文件夹
├── server.js                 # 网页版服务（手动补传的备用方案）
├── public/                   # 网页版手机端 PWA
└── test/e2e.js               # 端到端自测（31 项）
```

### 网页版是什么

`server.js` 是早期的网页方案，现在**不是主路径**，只在你想手动补传特定照片时用。
Syncthing 才是自动同步的主方案。

停掉网页版：

```bash
lsof -ti tcp:8848 | xargs kill
```

## 开发

```bash
npm test                # 31 项端到端自测
node server.js          # 手动启动网页版服务
```

**一条重要的开发经验：**

装完之后必须**真查 Syncthing 有没有加载共享文件夹**，不能只看配置文件写了没。
我踩过这个坑：配置文件写好了、验证脚本报「全部通过」，
但 Syncthing 加载了 0 个文件夹 —— 因为 `<folder>` 被放进了 `<defaults>` 容器
（那是默认模板，不是真实文件夹），XML 结构非法，Syncthing 直接忽略整个文件。

所以 `setup-folder-api.py` 走 REST API 而不是改 XML，
一键安装器的 6 项验证里这项最关键。
